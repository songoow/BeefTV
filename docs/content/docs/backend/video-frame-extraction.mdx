# 工作流视频截帧

工作流的 `video.frame` 操作接收一个已就绪的视频资源，输出可继续连接到生成节点的 PNG 图片。处理在本机媒体任务中执行，不调用生成模型。

## 截帧方式

| 参数 | 用法 |
| --- | --- |
| `mode: "timestamp"` | 按 `seconds` 指定的时间截帧。省略 `mode` 时沿用此行为。 |
| `mode: "last"` | 提取第一个视频流真正解码出的最后一帧，不需要 `seconds`。 |
| `seconds` | 指定时间模式的非负秒数，必须小于已知视频时长。实际末帧模式不使用此参数。 |

实际末帧节点示例：

```json
{
  "id": "segment-a-last-frame",
  "title": "前段实际末帧",
  "role": "operation",
  "mediaType": "image",
  "operationId": "video.frame",
  "operationVersion": 1,
  "config": { "mode": "last" }
}
```

将前段生成节点的 `output` 连接到该节点的 `video` 端口，再将该节点的 `output` 连接到后段生成节点的 `referenceImages`。工作流等待前段视频保存为就绪资源后才截帧，等待 PNG 保存后才提交依赖它的后段任务。后段参考图如何参与生成仍由所选模型和参考模式决定。

## 实际末帧如何确定

媒体工具先对本机源文件的 `v:0` 视频流顺序解码计数，再对同一视频流顺序解码并按零起始帧序号选取最后一帧。两遍处理都受原任务的取消与执行期限约束，输出通过原有资源保存和任务交付流程落盘。

选择不依赖容器声明时长、平均帧率或「时长减去 100 毫秒」估计。可变帧率、单帧视频和比视频更长的音轨不会把截帧位置移到错误时间；多视频流文件明确选择第一个视频流。输出保留 FFmpeg 对该视频流的正常显示方向处理。

完整顺序解码需要读取视频两遍，耗时随视频长度和解码成本增加；不会使用把整片画面缓存到内存的反转滤镜。源文件和输出文件只在媒体任务临时目录中处理。没有可解码视频帧、媒体工具失败或任务超时时会报告失败或取消，不回退到首帧或猜测时间点。

实际末帧模式需要本机的 FFmpeg 和 FFprobe。工作流保存校验和新运行入队前会检查两个工具的可执行路径；缺失时提前拒绝，不会先提交前段生成。指定时间模式沿用 FFmpeg 截帧，不因 FFprobe 缺失而被禁用。

## 恢复与质量边界

操作沿用媒体任务的素材归属校验、稳定提交编号和产物恢复。已有就绪 PNG 可按原任务取回，不需要再次解码；任务取消不会提交依赖该结果的新步骤。

「实际末帧」表示视频流的最后一幅可解码画面。它可能是黑场、字幕、转场或不适合接续的姿态；此操作不判断人物、动作或接缝质量。需要人工挑选更合适的接续位置时，使用指定时间模式并检查输出图片。
