# 双段连续视频工作流

画布的工作流库提供“使用双段视频模板”入口。模板先生成前段，再从前段成片提取实际末帧，最后把角色造型图、这个末帧和后段动作视频一起送入后段生成。它使用现有工作流编辑器、模板版本、依赖校验和任务运行机制；创建模板只打开草稿，保存后加入画布并点击运行才会提交生成任务。

## 三种起步方式

| 入口 | 每次需要填入的素材 | 执行与输出 |
| --- | --- | --- |
| 双段连续视频 | 最终角色造型图、前段动作视频、后段动作视频 | 生成前段 → 提取实际末帧 → 生成后段，保留三个结果 |
| 双段视频 · 前段与末帧 | 最终角色造型图、前段动作视频 | 生成前段并提取实际末帧，供人工验收 |
| 双段视频 · 从已验收前段续接 | 同一版本角色造型图、已验收前段成片、后段动作视频 | 从输入成片重新提取实际末帧，只生成后段 |

完整双段模板会在依赖任务成功后继续执行，没有中途人工验收闸门。需要先检查前段、控制返工范围时，使用后两个分段模板。

## 素材分别负责什么

角色身份和角色造型应先在最终参考图中确认。情侣双人画面尤其要明确两人的对应关系：谁对应哪个角色、各自的脸部特征、发型与服饰，以及左右位置或互动方向。参考图应让这两个人和最终头身比例都清楚可辨。

| 参考 | 负责的内容 | 使用约定 |
| --- | --- | --- |
| 身份依据 | 两个人是谁、各自的辨识特征 | 在制作最终造型图时核对，不把多套互相冲突的造型混入本模板 |
| 最终角色造型图 | 身份、头身比例、服饰配色、画面风格 | 前后段使用同一冻结版本，作为各自的第一张参考图 |
| 前段、后段动作视频 | 动作顺序、节奏、互动关系、镜头运动 | 只传给对应段落；提示词说明人物外观以造型图为准 |
| 前段实际末帧 | 接续时的位置、朝向、姿态、构图和光线 | 作为后段第二张参考图，保持角色主图仍然独立存在 |

模板提示词通过工作流节点引用绑定素材，保存、重命名或重新运行时仍按节点身份找到对应参考。后段固定使用“角色图为图片 1、末帧为图片 2、动作视频为视频 1”的槽位顺序，不把前段动作视频误传给后段。

两个生成节点都显式使用“参考素材（不固定首尾帧）”。末帧是连续性参考，后段首帧不受像素级硬约束；最终衔接仍需观看验收。需要强制首尾帧的其他项目应使用适合该模式的模型与配方，不能把这个模板的连续性参考等同于强制首帧。

## 创建与运行

1. 打开画布工作流库，点击“使用双段视频模板”，选择完整链或对应阶段。
2. 在生成节点的属性中分别选择已启用的视频模型及渠道。模板不预置账号、API Key 或厂商模型；应选择能接受所需参考图片和参考视频组合的模型，后段需要同时接受两张图片和一段视频。
3. 确认前后段的比例、清晰度、提示词和时长。示例默认前段 11 秒、后段 10 秒，这两个值可以修改；模型允许的时长、参考数量与其他限制仍由现有能力校验处理。
4. 保存工作流并加入画布，为输入槽填入已保存的素材。前段与后段动作输入保留不同名称，避免填反。
5. 点击运行，完成后检查输出。使用分段流程时，先保留通过验收的前段成片，再把它填到续接模板的“已验收前段成片”输入。

本地实际末帧提取依赖 FFmpeg 和 FFprobe，保存与新运行入队前会检查两个工具是否可用。参考图片和视频如何上传、内联或通过 URL 传给模型，使用所选模型的素材传输配置；这个模板不会另建上传服务，也不会绕过模型的输入校验。

## 阶段冻结与定向返工

先冻结造型，再冻结前段，最后验收后段。为每次通过验收的造型图和成片保留清楚的版本名称，连同所用模板版本、提示词和参数一起保存。

- 如果只是后段的动作或表情不满意，继续使用同一张角色造型图和同一段已验收前段，调整后段提示词或动作参考，重新运行续接模板。前段不需要再次生成。
- 如果前段的动作不满意，用“前段与末帧”模板生成新版本。确认新前段后，再用它接续后段；旧后段依据的是旧末帧，需要重新判断是否还能使用。
- 如果要求整体“更 Q”、改变头身比例、脸型或服装，先制作并验收新的角色造型图，然后从前段重新生成。仅在后段提示词加“更 Q”会让两段依据不同的造型标准。

续接模板每次从选定的前段成片重新提取末帧，避免沿用另一版前段留下的截图。已验收素材以输入形式复用，任务运行状态不承担“审美通过”的含义。

## 质量验收与失败恢复

任务成功表示执行与产物交付完成，不代表人物、风格和连续性通过验收。建议逐段完整观看，并把两段交界处放慢检查：

- **身份与造型：** 两人是否可辨、是否互换身份，头身比例、发型和服饰是否与冻结参考一致。
- **动作与互动：** 动作顺序、节奏、接触关系、视线和运动方向是否合理，四肢和手部是否出现明显畸变。
- **段间连续性：** 前段末帧与后段开头的人物位置、姿态、相机角度、背景与光线是否跳变。
- **交付：** 两段能否正常播放，时长和画面比例是否符合本次要求；合并、配音或字幕完成后还需验收最终成片。

“重试失败步骤”沿用现有失败恢复机制，用于处理未完成的任务、提交或产物交付问题。它不会把已经成功但画面不满意的步骤当作失败。质量不满意时应保存新参数或替换参考素材，再启动新运行；局部修改优先使用对应的分段模板。完整双段模板的新运行会再次执行两次生成。

## 配方与实现边界

工作流节点 `generate.video` 的公开编辑参数可以显式保存：

```json
{
  "videoEditOperation": "reference_to_video",
  "videoSeconds": 10
}
```

编译器把 `videoEditOperation` 写入既有生成任务的 `metadata.videoEditOperation`，交给原有协议适配层处理；不接受模板自带端点或凭据。未提供此编辑参数的历史工作流保留原配方。显式选择参考模式或自动模式会清除原配方的首、中、尾帧角色和旧草稿定稿绑定，选择自动模式以空串保存并交回模型默认处理。保存和重新打开编辑器都会保留这项选择。

末帧节点使用 `operationId: "video.frame"`、`config: { "mode": "last" }`，从前段输出视频提取最后一个解码帧，不用声明时长估算截图位置。后段依赖该节点成功并交付可用图片后才会提交。模板不会自动做人物相似度评分、审美打分、无缝衔接保证或最终视频合并。

模板工厂位于 `web/src/lib/canvas/continuous-video-workflow.ts`，入口在 `web/src/pages/canvas/canvas-workflow-workspace.tsx`；视频参考语义的编译与编辑回读位于 `backend/internal/canvasworkflow/`。行为测试覆盖模板图、素材槽位、阶段隔离、原生画布实例化、旧配方兼容与协议参考角色；这些测试不调用付费模型。
